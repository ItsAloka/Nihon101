## Important notes & decisions
- **The footer bug is the one to remember.** We first set the footer to `client:visible`; that never hydrates until you scroll to it, and the footer's text colours come from the JS palette while SSR always renders the *light* one. So a dark-mode reader would scroll into `#1A1817` text on a dark background — 1.19:1, unreadable. Lighthouse never caught it because it audits in light mode. Now `client:idle`. Lesson: any island whose colours come from the palette object must hydrate on idle, not on visible.
- A `rel=preload` next to the async font sheet is tempting and **wrong** — it puts the same quarter-megabyte back at high priority and starves the LCP image. We measured FCP getting *worse*. Don't re-add it.
- `home-chrome.jsx` is the only island without `withBoundary`, so making the login modal a lazy chunk needed an explicit ErrorBoundary — otherwise a failed chunk load unmounts the entire header.
- Owner chose "darken only the failing text" for contrast. `--inkFaint` stays exactly as designed for hairlines and icon strokes; only text moved to `--inkMeta`.
- Skipped maintenance mode on this deploy on purpose — no DB migrations, and old/new frontend and backend are compatible in both directions.
