## What we did
Ran a full senior-engineer audit of the backend. Verdict up front: the codebase is genuinely production-tier — auth, SQL safety, XSS sanitize-on-write, like/save race-safety, three-tier rate limiting, and admin authz are all already solid. The real gaps were a couple of security edges and two tables that grow forever.

Fixed 6 things (several were Nihon101-only catch-ups — Not Bagel already had them):
- **Google sign-in account pre-hijack (the important one).** Before, "Sign in with Google" would link to any existing local account by email match alone. So someone could pre-register *your* email with a password (accounts go live before verification), and after you signed in with Google you'd land in *their* account. Now: we only trust Google's email when Google says it's verified, and if the matched local account was never verified we **reclaim** it — mark it verified, wipe the pre-set password, revoke its sessions — before linking. Also now actually checks Google's `email_verified` claim.
- **Follower fan-out moved off the publish request.** Publishing no longer waits to write a notification to every follower — it runs in the background (`waitUntil`). A big-following author's Publish returns instantly now.
- **Two forever-growing tables now swept hourly** by the existing cron: read notifications older than 30 days, and taste signals (`user_signals`) past the For-You window. Both are safe deletes — every reader of those tables already ignores rows that old.
- **For-You ranking** now scores each post once instead of re-scoring inside the sort comparator (small but real speed win at scale).
- **CSP** cleaned up so the API origin can't drift from where the app actually fetches (caught + reverted a version that would've blocked the real API in prod).
- **Google token decode** is UTF-8-safe now, so Japanese display names don't turn to mojibake.

All verified: **backend typecheck clean, frontend build clean.**

## Important notes & decisions
- We did the SAME fixes in **both** projects (sisters — only real difference is Nihon101 is bilingual JA+EN). Fan-out, env-derived CSP, and the `email_verified` check were already in Not Bagel, so those were Nihon101-only.
- **No DB migration** — the prunes reuse existing columns + indexes; nothing else touched the schema.
- The "reclaim unverified account on Google sign-in" is deliberate: if you registered with a password but never verified, a Google sign-in with that same (Google-verified) email will null your password. You just reset it. Standard pre-hijack defense.
- Prune horizon for `user_signals` is tied to the For-You `SLOW.window` (+7-day margin) so it can never delete a row a feed still reads.
