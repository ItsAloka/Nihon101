**Focus:** Cut the Neon database bill — it was running too high because the compute never slept. Ported the exact fix Not Bagel shipped today (`v0.1NB`).

## What we did
- Found the root cause: the trending cron ran **every minute**, which reset Neon's 5-minute idle timer over and over, so the compute never scaled to zero — it sat awake 24/7 at 0.25 CU. Two smaller leaks too: anonymous readers hit the live DB, and the notification badge polled every 60s (a left-open tab kept the DB awake).
- Fixed all three, matching Not Bagel:
  - **Cron every minute → every 30 min** (`*/30`), same as Not Bagel (owner wanted the two sites symmetrical).
  - **Idle gate:** the cron now SKIPS opening Postgres on any tick where nothing happened — no new engagement (a KV `trending:dirty` flag) and no post waiting to be translated (a KV `translate:dirty` flag). So on a quiet stretch Neon sleeps. Top-of-the-hour always runs. Nihon needed the second flag because it also drains a translation queue in the same cron — that's the one real difference from Not Bagel.
  - **Anonymous readers** now read post counts + profile stats from the cached handle (signed-in users still read live), so logged-out browsing never wakes the DB.
  - **Notification badge** polls every **10 min** (was 60s) and stops while the tab is hidden. 10 min is longer than Neon's 5-min idle window, so a forgotten open tab can't pin the DB awake. (Not Bagel used 2 min; we later bumped Not Bagel to 10 min too, in its working tree — uncommitted, owner deploys NB later.)
