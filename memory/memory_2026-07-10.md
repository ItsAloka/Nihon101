## 8. Rate limiter fail-open — found here, fixed in BOTH repos

missing it silently downgrades DO → KV → per-isolate memory, so brute-force protection
becomes a no-op with zero symptoms. Owner fixed NB first (`83f50e4`), then we ported the
same 15 lines here as `d4f98c3`: missing binding = fatal 500 `insecure_config` in prod,
one loud `rate_limit_fallback_active` warn per isolate in local dev. Probed all 3 modes
against the real worker (prod-missing 500s and KEEPS 500ing; dev-missing warns + 200;
prod-present silent 200). Test env uses `localhost:4321` → warn path, 45/45 still green.

**How this was found:** a stale `wrangler dev` on :8787 (started before the bindings existed)
was silently unlimited — 15 bad logins, zero 429s. A fresh start listed the bindings and
tripped at exactly 10. **If rate limits look dead locally, restart the backend.**
